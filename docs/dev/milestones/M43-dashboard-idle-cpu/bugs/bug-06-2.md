# Bug 2 on phase-06: the activity fold is untested, masked by `#[allow(dead_code)]`

**Severity:** major
**Status:** fixed (verified at review 2026-08-05)
**Filed:** 2026-08-04

## What's wrong

Two halves of the same defect.

**1. The `architect_activity` fold has zero test coverage.** Spec §2 requires
`record == "architect_activity"` lines to be folded last-write-wins on
`(phase_id, activity, ts)`, and `select_lines` implements it
(`mcp/src/compact.rs:246`). No test exercises that branch.

**Proven by mutation.** Changing the fold to keep the **first** record per key
instead of the last:

```rust
                    if let Some(&_out_idx) = activity_latest.get(&key) {
                        // MUTATION: keep FIRST instead of last
                    } else {
```

```
test result: ok. 13 passed; 0 failed; 0 ignored; 0 measured; 697 filtered out
```

The fold can be inverted and nothing notices. The ledger fold has
`compact_keeps_only_the_last_ledger_per_key`, which correctly asserts on a
distinguishing field value — the activity fold needs the equivalent and has
nothing.

This is not hypothetical: on the real store the activity fold is doing real work
(323 activity records → 104), so an inversion would silently change which
activity records survive a one-way migration of the user's data.

**2. A `#[allow(dead_code)]` was added to hide the gap** rather than close it —
`mcp/src/compact.rs:471`:

```rust
    #[allow(dead_code)]
    fn activity_line(phase_id: &str, activity: &str, ts: u64) -> String {
```

The completion summary states this openly: *"The `activity_line` test helper is
`#[allow(dead_code)]` since no test currently exercises the activity fold path —
it's a fixture for future tests."* The fixture was built, the test was not
written, and the resulting warning was silenced.

`STANDARDS.md` §1 is explicit: *"No `#[allow(...)]`, `#[ignore]`, or
lint-silencing shims to mask diagnostics."* The dead-code warning here was the
tooling correctly reporting missing coverage, and the `#[allow]` turned that
signal off.

## What should happen

The fixture gets used by a real test, and the `#[allow(dead_code)]` disappears
because it is no longer dead.

## How to fix

In `mcp/src/compact.rs`:

1. Add `compact_keeps_only_the_last_activity_per_key`, modelled on the existing
   `compact_keeps_only_the_last_ledger_per_key` (`:521`). Seed three activity
   lines via the existing `activity_line` helper: two sharing a
   `(phase_id, activity, ts)` key and one differing. Assert the output has two
   lines **and** that the surviving duplicate is the later one — assert on a
   distinguishing field value, not just the count, exactly as the ledger test
   does. Note `activity_line` as written varies only the key fields, so add a
   distinguishing field (or a parameter) that lets the test tell the two apart.
2. Delete the `#[allow(dead_code)]` at `:471`.
3. Confirm `cargo clippy --all-targets --all-features -- -D warnings` is still
   clean without it.
