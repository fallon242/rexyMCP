# Bug 1 on phase-04: the memoization delivers no measurable improvement

**Severity:** blocker
**Status:** open
**Filed:** 2026-08-04

## What's wrong

The `TranscriptCache` is implemented exactly as specced and works — but quiescent
idle CPU is **unchanged**. Measured at review by alternating the phase-03 binary
(`acae94e`) and the phase-04 binary in one session, 10 s quiescent windows,
process selected by `/proc/<pid>/comm`:

| Binary   | large session log (1.5 MB) | trivial session log |
| -------- | -------------------------- | ------------------- |
| phase-03 | 198, 201 ticks             | 1, 0 ticks          |
| phase-04 | 200, 200 ticks             | 1, 0 ticks          |

The positive control is healthy — 198 vs 1 proves the harness is sensitive to
exactly the work this phase targets — and phase-04 is indistinguishable from
phase-03. The acceptance criterion "quiescent falls by **≥ 2×**" is not met; the
measured ratio is 1.0.

**Root cause: the spec's own instruction.** `mcp/src/dashboard/render.rs`, the
filter-closed branch:

```rust
        let wrapped = cache
            .get(state.generation, &data.records, &filter_state.filter, wrap_width, INDENT)
            .to_vec();
```

The phase doc told you to write that `.to_vec()`, and asserted "cloning the
wrapped `Vec` is far cheaper than rebuilding it." **That assertion was wrong.**
Each `Line` owns `Span`s which own `String`s, so cloning the whole vector deep-copies
every styled fragment of every record — work proportional to the entire transcript,
on every tick. It reproduces the cost the cache removed. Handing all lines to
`Paragraph::new(...)` and letting it scroll internally is a second O(all lines)
pass per tick.

This is a **spec defect, not an implementation defect**. The code faithfully
implements what was written.

**Secondary — the verification that would have caught it was not run.** The phase
doc's "End-to-end verification" required an A/B measurement with an explicit
positive control (STANDARDS § 1.1), plus a behavioral liveness check. Neither
appears in the completion Update Log or the summary; only the four command
outputs do. A phase whose entire purpose is a CPU reduction cannot be reported
complete without measuring the CPU.

**Tertiary — one test cannot fail the way it is meant to.**
`transcript_cache_rebuilds_when_width_changes` asserts:

```rust
        assert!(
            r_narrow_len >= r_wide_len,
            "narrower width must wrap to at least as many lines"
        );
```

`>=` holds trivially when the cache ignores width entirely and returns the same
lines both times — which is the exact bug the test is named for.

## What should happen

Quiescent idle CPU with a 1.5 MB session log falls by **≥ 2×** against the
phase-03 binary, measured by alternating A/B in one session, with the
large-vs-trivial positive control reporting a non-zero difference on the
comparison binary.

## How to fix

**1. Clone only the visible window, not the whole transcript**
(`mcp/src/dashboard/render.rs`, filter-closed branch). The `Paragraph` for this
pane has **no** `.wrap(...)` configured, so wrapped lines map 1:1 onto terminal
rows — slicing to the viewport and dropping `.scroll(...)` renders identically:

```rust
        let all = cache.get(
            state.generation,
            &data.records,
            &filter_state.filter,
            wrap_width,
            INDENT,
        );
        total_wrapped = all.len();
        let viewport = activity_area.height.saturating_sub(2);
        let scroll = visible_offset(state.follow, state.offset, total_wrapped, viewport);

        // Clone only the rows that will actually be drawn. Cloning every line
        // deep-copies each Span's String and costs as much as rebuilding.
        let start = (scroll as usize).min(total_wrapped);
        let end = start.saturating_add(viewport as usize).min(total_wrapped);
        let visible: Vec<Line<'static>> = all[start..end].to_vec();

        frame.render_widget(
            Paragraph::new(visible).block(
                Block::default()
                    .borders(Borders::ALL)
                    .title(" Activity [f=filter] "),
            ),
            activity_area,
        );
```

Note `.scroll((scroll, 0))` is **removed** — the slice already positioned the
window. Keep `total_wrapped` as the full count: the scrollbar below it, and
`clamp_scroll` in the event loop, both depend on the full length, not the slice.

The filter-open branch already takes only `.len()` and needs no change.

**2. Fix the width test** — change `>=` to `>` in
`transcript_cache_rebuilds_when_width_changes`, and pick two widths that
demonstrably differ (a record whose text exceeds the narrow width). If the
assertion cannot be made strict, the test is not pinning anything.

**3. Run the end-to-end verification** in the phase doc's "End-to-end
verification" section, including the positive control, and quote the numbers in
the Update Log.

## Verification

- [ ] `cargo fmt --all --check`, `cargo build`, `cargo clippy --all-targets
      --all-features -- -D warnings`, `cargo test` all pass.
- [ ] `transcript_cache_rebuilds_when_width_changes` asserts a strict `>`.
- [ ] The A/B harness reports phase-04 quiescent ticks **≤ half** the phase-03

- [ ] The positive control (same binary, large vs trivial session log) reports a

      reported as such rather than as a pass.
