# Bug 1 on phase-08: a debug `eprintln!` prints detected PII terms

**Severity:** nit
**Status:** waived by the user, 2026-09-17 (the line is still in the tree)
**Filed:** 2026-09-17

## What's wrong

`executor/src/privacy/egress.rs:557`, inside
`live_build_egress_index_keeps_project_names_out`:

```rust
        eprintln!("live terms: {terms:?}");
```

`STANDARDS.md` §1 says "No `dbg!`, `println!` debug calls, or commented-out
code." That box has no test exemption — unlike the `unwrap()` box, which says
test code is exempt, so the omission is deliberate.

The line also prints whatever the pre-scan detected. Here that is synthetic
(`Alice Fernandez`), and the test is `#[ignore]`d, so nothing real leaks. But
printing the contents of a PII dictionary is the wrong reflex to leave in the
privacy module, and it is what the phase-09 spec already ruled out in writing:
"`println!`/`eprintln!` must not stay in the code."

Everything else in this phase passes. The architect's independent re-run:
fmt/build/clippy clean, `cargo test` 716 + 2 + 1174 (10 ignored), both live
tests green against the real engine, and the committed `PiiIndex::retaining`
filters correctly.

## What should happen

The assertion messages already carry the terms when they fail
(`"…got {terms:?}"`), so the line can simply go. No other change.

## Root cause

Instrumentation added while iterating on the live test, and not removed before
the commit.
