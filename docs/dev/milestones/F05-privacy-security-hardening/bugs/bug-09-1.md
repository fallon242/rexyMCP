# Bug 1 on phase-09: the live test counts 15 names instead of 300, and the E2E was never run

**Severity:** major
**Status:** fixed (e6e8c5d)
**Filed:** 2026-09-17

## What's wrong

The implementation is right. The architect replayed the phase's own logic
against the live engine (4096-token cap, split on `finish_reason == "length"`,
16 KB pre-split): **300 of 300 names found, 3 calls, 346 seconds.** The gates
pass and every hermetic test is real.

Two things are missing.

1. **`live_engine_survives_a_name_dense_file` can never pass.**
   `executor/src/privacy/ner.rs:468-476` counts matches with

   ```rust
           let found = spans
               .iter()
               .filter(|s| {
                   FIRSTS
                       .iter()
                       .zip(LASTS.iter())
                       .any(|(f, l)| s.text == format!("{f} {l}"))
               })
               .count();
   ```

   `zip` pairs the lists positionally, so it yields 15 names (`Alice Abbott`,
   `Bruno Brennan`, …), not the 300 the text holds. `found` can never exceed
   15, and the assertion demands `found >= 270`. The test fails whatever the
   engine returns.
2. **The End-to-end verification was not run.** The phase doc requires
   `/tmp/p09_live.txt` pasted into the Update Log. The Update Log has one
   entry, from the start of the run, and the completion summary does not
   mention the live run. Had it been run, item 1 would have failed.

## What should happen

`found` counts how many of the 300 `"{first} {last}"` names appear as the text
of some span, and the live test passes against the real engine. The E2E output
is pasted into the Update Log, as `STANDARDS.md` §1 requires.

## Root cause

`FIRSTS.iter().zip(LASTS.iter())` walks the two lists in step. The text is
built from the **cross product** of the same two lists, in nested loops at
`ner.rs:452-457`. The test never ran, so the mismatch was not caught.
