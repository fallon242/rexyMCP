# Bug 1 on phase-11: a weakened phase-07 test, a garbled symlink message, and the wrong remedy for a missing `.git`

**Severity:** minor
**Status:** open
**Filed:** 2026-09-17

## What's wrong

The security fix works. An independent re-run passes all gates and the 4
bubblewrap-only tests. With the `.git` self-bind removed,
`sandbox_protects_git_and_config` fails on `mv .git g2`, so that test guards
the property. Three smaller problems remain.

1. **A phase-07 test no longer tests anything useful.**
   `argv_without_home_has_no_toolchain_binds`
   (`executor/src/security/sandbox.rs:304-311`) used to assert that no element
   is `--ro-bind-try`. Row 9c adds an always-present
   `--ro-bind-try <root>/rexymcp.toml`, which broke that assertion. The
   executor changed the assertion to
   `!a.iter().any(|x| x == "/home/u/.cargo/registry")`. The test passes
   `home = None`, so no `/home/u/...` path can ever appear, and the assertion
   catches almost no regression. The spec said phase 07's tests would pass
   unmodified. That was the architect's error, but the executor weakened the
   test instead of filing a blocker.
2. **The symlink refusal doubles `.git`.** `sandbox.rs:53` formats
   `"{}.git is a symlink; …"` with `git.display()`, and `git` already ends in
   `.git`. The message reads `/path/repo/.git.git is a symlink`.
   `for_repo_refuses_symlinked_git` only checks for `symlink`, so it passes.
3. **The no-`.git` refusal gives the wrong remedy.** `run_phase` wraps
   `for_repo`'s error in `sandbox_refusal`, so the CLI prints
   `the bash sandbox is unavailable (… has no .git …) … Install bubblewrap (the
   bwrap binary) and check that unprivileged user namespaces are enabled …`.
   bubblewrap is installed and working. The fix is `git init`, or running from
   the repo root. The spec told the executor to reuse `sandbox_refusal`, so
   this part is the architect's error.

## What should happen

1. `argv_without_home_has_no_toolchain_binds` fails if any toolchain bind
   appears when `home` is `None`. The only `--ro-bind-try` allowed is the
   `rexymcp.toml` one.
2. The symlink refusal names the path once: `/path/repo/.git is a symlink`.
3. A `for_repo` failure produces its own refusal, which names `git init` and
   the local-executor fallback and does not mention bubblewrap.

## Root cause

1. The spec added an always-present `--ro-bind-try`, which contradicted an
   existing assertion. The spec wrongly promised that those tests would pass
   unchanged.
2. A format string appends `.git` to a path that already ends in `.git`.
3. The spec reused `sandbox_refusal`, whose remedy text is specific to a
   failed bwrap probe.
