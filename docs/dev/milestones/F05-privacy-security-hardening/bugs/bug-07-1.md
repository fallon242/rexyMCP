# Bug 1 on phase-07: sandbox test drops the `~/.config` check and writes to the host

**Severity:** major
**Status:** fixed (86d6f0d)
**Filed:** 2026-09-16

## What's wrong

`sandbox_blocks_home_and_state_dir` (`executor/src/security/sandbox.rs:220-272`)
does not test one acceptance criterion and is not hermetic.

1. **No `$HOME/.config` check.** The criterion says a sandboxed `bash`
   "cannot see `$HOME/.config`". The test never runs `test -e "$HOME/.config"`
   (`grep -c '\.config' executor/src/security/sandbox.rs` → `0`). The Update
   Log says the check "was always skipped because the home tmpfs is empty".
   That is wrong: an empty home tmpfs is what makes the check pass. The check
   is skipped only when the **host** has no `~/.config`.
2. **It writes outside its `TempDir`.** Lines 236-237 create
   `/var/tmp/rexymcp-p07-home` on the host. Line 241 then spawns the sandbox
   with `HOME` set to that directory, while the `Sandbox` was built from the
   real `$HOME`. So the `touch` check proves only that `/var/tmp` is read-only.
   It does not test the home that production hides.

The production code is correct. The architect ran it by hand on bubblewrap
0.12.0 with the real `$HOME`, using the argv from `Sandbox::argv`:

```
config_visible_exit=1      # host: test -e ~/.config → 0
touch_exit=0               # "$HOME/x" inside the sandbox
host ~/x absent            # the write did not reach the host
```

## What should happen

The ignored test guards the finding-10 fix, so it must check the real
properties against the real `$HOME`:

- `$HOME/.config` is not visible inside the sandbox when the host has one.
- A write under `$HOME` does **not reach the host**.

**Spec correction (architect's fault, spec § Test plan 5):** the spec said
`touch "$HOME/.sandbox-probe"` must exit non-zero. With the real `$HOME`, the
`--ro-bind-try <home>/.rustup` mount makes bwrap create `<home>` inside the
`/home` tmpfs, so the `touch` **succeeds** on the tmpfs. The property that
matters is that the file never appears on the host. The phase doc's Test
plan 5 is updated to say this.

## Root cause

The spec's `touch` check could not pass with the real `$HOME` (see above).
The executor worked around it by changing `HOME` rather than filing a blocker,
and dropped the `~/.config` check on a wrong reading of why it passed.
